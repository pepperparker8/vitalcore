# CLAUDE.md: VitalCore

## Project
VitalCore is a personal health intelligence PWA. It combines training load, sleep, daily psychology check-ins, body measurements, blood markers and injuries into one readiness score and an AI-generated daily briefing.

Current version: **7.0**. Built iteratively in claude.ai as an artifact. This repo is the move to a standalone, deployable app.

## User context
- Single user: an endurance athlete (running, cycling, hiking, weights, yoga). Swims (Swim is allowed, distance in metres).
- Primary device: Samsung Galaxy S24 (Android, Chrome). Minimum viewport 360px.
- Wearable: Polar Loop 2. Polar API is not accessible (403). Do not rebuild a Polar connection.
- Training data: Intervals.icu (CTL, ATL, TSB, PRs).
- Blood tests come from Indonesian labs: all markers in **mg/dL**, never mmol/L.
- AI: Anthropic Messages API with the user's own key.

## Architecture
- Vanilla HTML/CSS/JS, no framework, no build step. Hosted on GitHub Pages; Supabase for sync (local-first, RLS own rows).
- Layout: `index.html` (shell), `css/app.css`, `js/` classic scripts sharing globals, loaded in this order: core, sync, strength, log, today, settings, render, recovery, chart, form, trends, progress, plan, review, coach, strategy, fuel, health, digest, insights, app. `sw.js` caches the shell (add new files to SHELL and bump the cache name).
- External: Google Fonts only (IBM Plex Mono, Outfit, DM Serif Display).
- State: one in-memory object `_s`, accessed via `S()` and written via `save(d)`, which triggers a 400ms debounced persist.
- Charts: hand-drawn on `<canvas>` (mood, weight, fitness/fatigue/form and readiness trend via `mountChart()` in `js/chart.js`; the old `lineChart()` was removed in v89). Canvas colours come from `cssv('--name')`, so they follow the theme. Readiness is snapshotted daily in `readHist` (local only) and DOM bars (sleep, HRV sparkline, blood sparklines).

### State shape
```

workouts[]     {date, type, distKm, durMin, rpe 1-5 or null, notes, sets[], sub}  (sets: [{ex, muscle, kg, reps, secs, rir, kind, bw}]; sub: swim {pool, stroke}, Intervals.icu details {icu:{hr,hrMax,kcal,elev,load,rpe 1-10}})
sleepLogs[]    {date, score 0-100, durMin, deepH, deepM, remH, remM, rested, isEx}
```

### Key logic
- `calcReadiness()`: sleep score base (`slScore()`: the logged score, else estimated from time asleep vs goal, goal = 85), adjusted by TSB (positive adds, negative subtracts; v89 fixed the sign), blended 70/30 with latest check-in (sleep and check-in only count when from the last 3 days), HRV and resting HR nudge vs your 30-day baseline (`recoveryAdj()`, only with 7+ days of data), minus 8 per injury severity level, minus 4 per soreness level above mild (check-in `soreness`). Clamped 20 to 100.
- `calcBurnout()`: risk = 100 minus coping; coping is 60% psychological (7-day check-in averages) and 40% physical (from form: TSB 0 = 100, -40 = 0). Without Intervals.icu data it is psychological only. (v89 fixed an inversion where more fatigue lowered the risk.)
- **Stress is inverted** everywhere it feeds a score: 1 = calm (good), 4 = very stressed (bad). Always use `5 - stress`.
- Log > Workout is one form (v83; the separate Quick workout card is gone, do not bring it back): type grid, duration chips (`renderDurChips`), distance, then a collapsed "Date, effort and note". Above the form: "Last 7 days" list with Edit / Delete on every row (`wkRow`, `renderWkLog`, `delWorkout` with Undo that removes the tombstone). Intervals.icu rows carry a source tag. Deleted Intervals.icu workouts, sleep nights and weights stay deleted: `del()` records imported ids (`icu-`, `sl-`, `mi-`) in local-only `gone`, checked on import with `isGone()` (the tombstone alone is cleared after the cloud delete). `put()` clears a tombstone for the same record, so Undo and re-saving are safe.
- Duplicates (v83): `findDups()` pairs a hand-logged workout with an Intervals.icu one of the same type and date (last 30 days). `dupHTML()` shows a strip in Log and in Today's list: "Combine into one" (`mergeDup`: keeps the Intervals record, copies effort, note, sets) or "Keep both" (`keepDup`, stored in local-only `dupOk`).
- AI briefing (v83, `js/insights.js`): one briefing, no Weekly/Monthly toggle. `insightData()` builds today / week / month / trend / health / profile JSON; `INS_SYS` is the system prompt; reply is forced to JSON with structured outputs (`output_config.format` json_schema, `INS_SCHEMA`), falling back to a plain request and `parseInsight()` if rejected. `max_tokens` is 16000 because thinking tokens count toward it (1600 caused the cut-off "not in the expected format" error). Sections are listed in `INS_SECS`; old history entries still render. Failures show a plain reason plus `buildFallback()`.
- Briefing memory and follow-ups (v85): `insightData().previousBriefings` (`insPrev()`, last 3 before today) lets the model check its earlier advice in the `followup` section ("Since the last briefing"). The model also returns 3 `questions`, shown as chips under today's briefing with a free-text box (`insQaHTML`, `askInsight`, system prompt `INS_QA_SYS`, shared rules in `INS_COMMON`, plain-text answers, max 10 per briefing). The thread is stored on the briefing as `qa[{q,a,ts}]`, so it syncs inside the existing `rendered` JSON. Regenerate replaces the briefing only on success and keeps the thread. The phone keeps 365 briefings (`insCap()`; 60 with `insLean` after a storage-full save); sync pulls the newest 30 in full (newer `ts` wins, unsent local edits win) and older ones only when missing. History shows 20 at a time.
- Briefing data also includes 12 weekly trends (`insightTrends`), recovery drivers, all blood results with change (`insightBlood`) and code-computed Pearson correlations (`insightCorrelations`, needs 8+ paired days; includes coffee cups vs that night's sleep and previous-day load vs soreness). Model must not diagnose.
- Weekly plan (`js/plan.js`, stored in `profile.plan`): planned vs done per weekday; `suggestWorkout()` follows it when readiness allows and bends it (with a reason) when not. Trends has an interactive load chart (`renderLoad`) and Progress & PRs chart (`js/progress.js`); `lineChart()` supports touch scrubbing, PR `marks`, `yfmt`, `extra`.
- Today's session and 7-day outline (v86, `js/strategy.js`): `strategy()` returns 7 days starting today, each `{role, type, lo, hi, effort 1-5, name, how, why, bent}`, computed in code (the AI only explains it). `stWeek()` picks the week mode and minutes target from the 4-week mean: Building x1.07 when 7-day readiness is 65+, Holding steady, Recovering x0.85 (readiness under 50 or high burnout), Easier week x0.75 after three full weeks, Taper / Race week from `racePhase()`. With a weekly plan it follows the plan (notes like "tempo", "long", "easy" set the role) and bends today for a bad or warn verdict, soreness 3+, a hard day yesterday, injuries; without a plan it schedules from usual training days per week. Hard days never back to back, max two per 7 days, none with a moderate injury or under 4 logged workouts. `suggestWorkout()` is now a thin wrapper (day 0, null once trained). Today card `#sugCard` ("Today's session", or "Next session, tomorrow" once trained); Insights card `#stratCard` (`renderStrategy`). The goal card uses the same target. Briefing data carries it as `today.prescription` and `strategy`.
- Fuel today (v87, `js/fuel.js`, `#fuelCard` on Today under the session card): `fuelPlan()` computes protein, carbs and fat in grams from the latest logged weight, today's training (logged workouts, else `strategy().days[0]`) and `profile.nutGoal` (`keep` default, `lose`, `build`; Settings > Food goal). Carbs 3 to 8 g/kg by day level (rest, easy, mod, hard, big, race; at least 7 the day before a race; minus 1 when losing, plus 0.5 when building), protein 1.6 to 2.0 g/kg, fat fills the rest of the day's estimated energy use (v88; clamped 0.6 to 1.5 g/kg). After a session: 0.3 g/kg protein plus 0.5 or 1.0 g/kg carbs. Food portions come from the built-in `FU_FOODS` table (Indonesian staples). Never adjusted by blood results. No weight logged = empty state linking to Log > Body. The briefing gets the same numbers as `insightData().nutrition`.
- Food log and next-session fuelling (v88, `js/fuel.js`): Log > Food (`#lFood`) keeps one running calorie total per day with quick-add chips and optional protein (`addFood`, `resetFood`, `renderFood`; one record per day, id `fd-<date>`, so two devices merge). Meals came in v98 (see below). Estimated use = `fuRest()` (Mifflin-St Jeor from weight, height, age and `profile.sex` 'm'/'f'/unset = average, x 1.35 for daily living) plus training (`fuWk`: Intervals.icu kcal minus the resting share, else MET table `FU_MET` x minutes; strength minutes from sets via `fuMin`). It is an estimate: there is no all-day activity data. The Fuel card shows eaten vs target, "You may be eating too little" when 3+ of the last 7 logged days average 500+ kcal under use (800 when losing), and `fuNext()` advice before and during the next big session (today's if not yet done, else tomorrow's; carbs 1 g/kg before, 1.5 for a race; 30/45/60 g an hour by duration). Briefing data: `nutrition.estimatedUseKcal`, `eatenToday`, `lastWeekLogged`, `nextSession`. Sync: table `food_logs` (`docs/supabase-v88.sql`); `TBL.food.opt` makes sync skip it without failing when the table is missing (`noFoodTbl`, note `#fdCloud`).
- Coach card (`js/coach.js`, `renderCoach`, on Insights under the briefing): since v90 it is only "Things to watch" (`coachFlags()`), plus Plan this week and Load this week rows and a "based on N of 14 days" note. The verdict itself (`coachVerdict()`: green, hold, back off from readiness plus hard flags) is shown once, on Today (`renderVerdict`); do not repeat it on Insights.
- The check-in reminder (strip on Today, nav dot, Settings row, optional phone notification) was removed in v104 at the owner's request; `profile.remind` may still exist in old data and is ignored. Do not bring it back without asking.
- Today shows "What is driving recovery" under the gauges (`readinessFactors()`/`renderFactors()` in render.js: sleep vs goal, form, check-in, HRV and resting HR vs baseline, injuries; every row opens its detail sheet, v97).
- The 7-day recovery strip at the top of Today (`renderDays7`, `#d7`, v74) was removed in v105 at the owner's request; `readHist` is still snapshotted daily for the readiness trend chart. Do not bring the strip back without asking.
- "Training this week" card (`renderWeekLoad()` in render.js, `#wkLoad`): Mon-Sun minutes from `raceLoad()` on a bar with a shaded usual band = 0.8 to 1.2 x the 4-week mean (x race phase multiplier); note says above/in/below range and days left; hidden until two weeks of real workouts.
- "Last night" card (`renderSleepStages()` in render.js, `#slStages`): proportional deep / REM / light bar with hours and %, shown only when stages were logged; note when deep <13% or REM <20%. Also "Bedtime consistency" (SD of `bed` over the last 7 nights, 3+ needed; Steady <=30min, Varies <=60, Irregular); the card then shows even without stages.
- Today is results only; all inputs live in Log (opens on the first unfinished daily entry; progress bar; daily vs now-and-then groups) (Check-in, Mindfulness, Sleep, Workout with duration chips, Body, Blood, Injury). Sleep is entered as bedtime + wake-up (`bed`, `wake` on the log, synced since v79; duration is computed, midnight-safe by `slSpan()`), with deep, REM, score and rested optional. Today order: three gauges (Recovery ring, Strain, Sleep; `renderGauges()` in render.js. Strain = 21*(1-exp(-load/(1.2*ref))) from `dayLoad`, ref = 75th percentile of the last 60 days; target range comes from `coachVerdict()`; Sleep = last night vs `sleepGoal`; tonight's "Asleep by" target = `profile.wakeTime` minus `sleepNeed()` = goal + up to 45 min for strain + half of recent debt, capped 45, shown inside the sleep detail sheet since v97), verdict strip (`renderVerdict`, Train / Hold steady / Rest from `coachVerdict()`), weekly review, suggestion, check-in, reflection, then a collapsed "More today" holding everything else.
- Race mode (`js/today.js`): `racePhase()` from `profile.goalDate` (Base 56+ days, Build 28-55, Peak 14-27, Taper 7-13, Race week), `raceLoad()` compares this week's minutes to a phase target (4-week mean x phase multiplier). Goal card sits under the suggestion on Today.
- Monthly review (`js/review.js`, `renderMonthly`): Today card on the 1st to 3rd for the previous calendar month vs the month before; dismissed via `profile.monthSeen`.
- Weekly review (`js/review.js`): Today card Mon to Wed summarising the previous Mon-Sun (sessions, distance, plan adherence, sleep, readiness, new bests); dismissed via `profile.reviewSeen` (week key, synced). "Plan this week" opens the plan editor.
- Blood scoring (`scoreBM`): normal 90, borderline 55, high 20.

## Conventions
- Durations always hours + minutes via `fmtDur()` / `fmtHM()`. Never decimal hours in the UI.
- Check-in uses face icons, never numbers.
- Plain English labels ("How Fresh You Are", not "TSB") with a "Why this matters" expandable for the technical term.
- Validate inputs against physiological ranges with a friendly toast, never a silent save.
- Empty states always explain what to do next and link to the fix.

## Do not reintroduce
Polar connection section, duration/HR fields for weight training, decimal sleep hours, numeric check-in buttons, "Rest day" label for unlogged days.
